# Recruitment Shortlist

上海支付与策略运营岗位的静态筛选页面。公开数据来自互联网大厂、Airwallex、Mastercard、Adyen、Worldpay、汇付天下、易宝支付等公司官网及 BOSS 直聘，仅展示符合当前 A+/A-/B/C 规则的岗位摘要、匹配度、岗位属性、风险提示和原始链接。

筛选规则以工作地点上海为硬性标准，并严格依据简历中的支付 B 端产品运营、商户生命周期、实验增长、行业解决方案和销售赋能经历。A+ 只保留支付主线的直接匹配；A- 保留支付相邻岗位，以及可明确复用 B 端产品、商户生命周期或 GTM 能力的岗位；电商类目、广告内容、海外当地资源、消费信贷等核心背景缺口会进入 B。匹配度和分档使用相同规则：A+ 为 90-100、A- 为 75-89、B 为 45-74、C 为 0-44，同档内再按简历证据减去硬缺口惩罚排序。

网页包含独立的技能提升页。能力指南以建立时的 68 个 A 档岗位为样本，把重叠内容整理为边界清晰的技能域：P0 合并通用底盘与支付、英语、国际市场核心专项，P1 保留电商经营、研究洞察和实验验证；点击提升计划后直接显示技能总览，也可从左侧目录进入单项训练。核心能力中的六项设有懒加载题库，共 42 章 668 题：业务英语为 10 个主题关卡、每关 50 题，数据分析与经营诊断为 8 章 48 题，其余四项各 6 章 30 题。核心词汇作为独立首项，提供 500 个带美式音标的支付业务词条，可按常用程度或字母 A-Z 排序。所有题库只使用单选和排序等点击式交互，可跳过作答、直接查看参考答案或自由切换题目；词汇表支持分别遮盖中文释义、英文例句和中文翻译，并记录掌握状态。

面试提升页位于 `#interview`，会从每天更新的 `jobs.json` 动态读取当前 A+ 与 A- 岗位，并内置 WorldTrade 支付增长运营专项。页面保留 12 道核心训练题和 69 道高频岗位题，其中新增 50 道 WorldTrade 专项题，覆盖支付链路、商家增长、风控合规、经营分析、国际协同和常见行为面试；12 道题由公开面经脱敏转写，其余依据官方公开产品边界设计。每题都有重新组织的参考范文、事实边界、回答框架、追问和失分点，题库可按关键词和方向筛选。页面聚焦选题、回答、反馈和范文，回答提示、真实经历卡与录音按需折叠；首次检查只给出一个应保留点和一个优先改进点，修改后可保存复练版、比较两个版本并完成一道追问。最多七张“真实经历卡”可复用到不同题目；固定 WorldTrade 范文会直接显示，选择其他岗位时仍保留改写提醒。

文字回答、两版检查记录、目标岗位、经历卡、追问和录音都只保存在当前浏览器，不会上传。录音使用 IndexedDB 自动留档，每题保留最近 3 条，全站最多 30 条且总量不超过约 100 MB；达到上限时自动删除最旧录音，页面被系统中断时不保存不完整的新录音。清除站点数据、使用无痕模式或浏览器回收存储空间仍可能删除留档，因此它不是长期备份。关键词检查只是一种弱提示，不判断经历真伪、因果逻辑、回答质量或录用概率，也不应为了通过检查堆术语或编数字。核心题存放在 `interview-plan.json`，通用高频题及答题指南存放在 `interview-question-bank.json`，新增 WorldTrade 题目、题源与范文存放在 `interview-worldtrade-extension.json`；题库加载失败时核心训练仍可使用，刷新岗位数据不会覆盖这些内容。

关卡首页会从未作答的内容中随机生成“今日五题”，当天题组保持不变，同时记录每周练习天数；完成章节后会解锁一张可复用的速查卡。通用技能内容独立存放在 `learning-guide.json`，六套 P0 题库存放在 `challenges/` 并仅在进入对应技能时懒加载；业务英语拆为轻量目录和 10 个关卡文件，核心词汇的数据独立存放在 `challenges/core-vocabulary/`。核心词汇的单词、例句和面试表达配有 Kokoro 离线生成的美式英语音频，点击后按需加载，音频缺失时回退到浏览器朗读。各题库的学习进度、每日任务、词汇掌握状态和点击选择分别保存在当前浏览器。内容依据上级项目中的 `sources/recruit/A档岗位能力提升完整指南.md` 整理，因此刷新岗位数据时不会覆盖学习内容。

## 本地运行

```bash
python3 -m http.server 4173
```

打开 `http://localhost:4173/`。

安装浏览器测试依赖并运行完整静态站点检查：

```bash
npm ci
npx playwright-core install chromium
npm test
```

## 生成核心词汇语音

语音构建依赖 Python 3.11、CPU 版 PyTorch 和 `scripts/glossary-audio-requirements.txt`。首次运行会下载 Kokoro 模型权重，之后支持断点续跑：

```bash
python scripts/build-glossary-audio.py
```

输出位于 `audio/core-vocabulary/`，共 1500 个按需加载的单声道 MP3。可以使用 `--start-rank` 和 `--end-rank` 分段并行生成，全部完成后运行 `python scripts/build-glossary-audio.py --manifest-only` 更新清单。

线上页面通过 jsDelivr 从固定 Git 提交按需读取这些音频，读取失败时回退到浏览器朗读。仓库使用单一 GitHub Actions Pages 工作流：先运行浏览器测试，再显式发布精简后的网页与题库文件；artifact 不重复打包音频，以避免大量小文件拖慢部署。本地运行仍保留全部音频源文件。仓库的 `Settings -> Pages -> Source` 必须设置为 `GitHub Actions`。

## 更新数据

在上级项目目录执行：

```bash
npm run refresh:recruitment
```

官网抓取配置位于 `sources/recruit/official-job-targets.json`。单个官网临时失败时会沿用上一版该来源的数据并标记为 stale；其他来源继续更新。提交并推送 `jobs.json` 后，GitHub Pages 会自动重新部署。
